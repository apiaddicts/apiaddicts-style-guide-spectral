API name must start with the prefix 'api-'

The API name is the first segment of the base path: the Swagger 2.0 `basePath`, or the path of each root `servers[*].url` in OpenAPI 3.x. It must start with `api-` followed by a name, for example `/api-seguros/v1`. Scheme, host, port, query and fragment are ignored, and relative URLs are evaluated by their path. A base path without segments (`https://petstore.swagger.io`, `/`) is reported.

Noncompliant Code Example (OpenAPI 2)
-------------------------------------

``` yaml
swagger: "2.0"
info:
  version: 1.0.0
  title: Swagger Petstore
basePath: /seguros/v1 # Noncompliant {{OAR099: API name must start with prefix 'api-'}}
paths: {}
```

Compliant Solution (OpenAPI 2)
------------------------------

``` yaml
swagger: "2.0"
info:
  version: 1.0.0
  title: Swagger Petstore
basePath: /api-seguros/v1
paths:
  /status:
    get:
      responses:
        200:
          description: Ok
```

Noncompliant Code Example (OpenAPI 3)
-------------------------------------

``` yaml
openapi: "3.0.0"
info:
  version: 1.0.0
  title: Swagger Petstore
servers:
  - url: https://petstore.swagger.io/seguros/v1 # Noncompliant {{OAR099: API name must start with prefix 'api-'}}
  - url: https://api-petstore.swagger.io/seguros/v1 # Noncompliant {{OAR099: API name must start with prefix 'api-'}}
  - url: https://petstore.swagger.io/v1/api-seguros # Noncompliant {{OAR099: API name must start with prefix 'api-'}}
paths: {}
```

Compliant Solution (OpenAPI 3)
------------------------------

``` yaml
openapi: "3.0.0"
info:
  version: 1.0.0
  title: Swagger Petstore
servers:
  - url: https://petstore.swagger.io/api-seguros/v1
  - url: /api-seguros/v1
paths:
  /status:
    get:
      responses:
        200:
          description: Ok
```
