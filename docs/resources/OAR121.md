Security schemes must only use the types allowed by the organization.

**Rules:**
- Applies to every security scheme declared in `securityDefinitions` (OpenAPI 2) or `components.securitySchemes` (OpenAPI 3). The issue is reported on `type`, or on `scheme` for the `http` type.
- The type must be one of the allowed types (case-insensitive): `apiKey`, `http`, `oauth2`, `openIdConnect`, `mutualTLS`, or an HTTP scheme such as `basic`, `bearer` or `digest`.
- An HTTP scheme allows only that scheme of the `http` type, while `http` allows all of them. The OpenAPI 2 `basic` type is HTTP basic, so `basic` or `http` allow it.
- A scheme is applied by an operation through its `security`, or through the root `security` when the operation has none (`security: []` applies nothing). Callbacks follow the path of their operation and webhooks have no path. In OpenAPI 3.2 a requirement can also reference a scheme by URI.
- With `/exclude` a scheme is skipped when every operation that applies it is under a listed path, and schemes applied by no operation are still checked. With `/include` only the schemes applied by operations under the listed paths are checked.
- Schemes reached through `$ref` are reported once, on the referenced definition.

**Configurable parameters:**

- `allowed-security-types` — allowed types, as an array or a comma-separated list (default: `oauth2,bearer`). A blank value falls back to the default.
- `paths` — path patterns to include/exclude, as an array or a comma-separated list; `*` matches one segment and `**` zero or more (default: `/me,/health,/ping,/status`).
- `pathValidationStrategy` — `/include` or `/exclude` (default: `/exclude`).


Noncompliant Code Example (OpenAPI 2)
-------------------------------------

swagger: "2.0"
info:
  version: 1.0.0
  title: Pet Clinic API
paths:
  /owners:
    get:
      security:
        - ClinicKey: []
      responses:
        200:
          description: Ok
securityDefinitions:
  ClinicKey:
    type: apiKey \# Noncompliant {{OAR121: Security scheme 'ClinicKey' type 'apiKey' is not allowed. Allowed types: oauth2, bearer.}}
    in: header
    name: X-Clinic-Key

Compliant Solution (OpenAPI 2)
------------------------------

swagger: "2.0"
info:
  version: 1.0.0
  title: Pet Clinic API
paths:
  /owners:
    get:
      security:
        - ClinicApp: []
      responses:
        200:
          description: Ok
securityDefinitions:
  ClinicApp:
    type: oauth2
    flow: application
    tokenUrl: https://auth.example.com/oauth/token
    scopes: {}

Noncompliant Code Example (OpenAPI 3)
-------------------------------------

openapi: 3.0.3
info:
  version: 1.0.0
  title: Partner Gateway API
security:
  - PartnerOAuth: []
  - LegacyBasic: []
paths:
  /orders:
    get:
      responses:
        200:
          description: Ok
components:
  securitySchemes:
    PartnerOAuth:
      type: oauth2
      flows:
        clientCredentials:
          tokenUrl: https://auth.example.com/oauth/token
          scopes: {}
    LegacyBasic:
      type: http
      scheme: basic \# Noncompliant {{OAR121: Security scheme 'LegacyBasic' type 'http' with scheme 'basic' is not allowed. Allowed types: oauth2, bearer.}}

Compliant Solution (OpenAPI 3)
------------------------------

openapi: 3.0.3
info:
  version: 1.0.0
  title: Partner Gateway API
security:
  - PartnerOAuth: []
  - ServiceBearer: []
paths:
  /orders:
    get:
      responses:
        200:
          description: Ok
components:
  securitySchemes:
    PartnerOAuth:
      type: oauth2
      flows:
        clientCredentials:
          tokenUrl: https://auth.example.com/oauth/token
          scopes: {}
    ServiceBearer:
      type: http
      scheme: bearer
      bearerFormat: JWT
