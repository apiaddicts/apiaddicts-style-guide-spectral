OAuth2 security schemes must only declare the flows allowed by the organization.

**Rules:**
- Applies to the `oauth2` security schemes declared in `securityDefinitions` (OpenAPI 2) or `components.securitySchemes` (OpenAPI 3). The issue is reported on the flow of the scheme definition.
- Every flow must be one of the allowed flows (case-insensitive). The OpenAPI 2 names are equivalent to the OpenAPI 3 ones: `accessCode` = `authorizationCode` and `application` = `clientCredentials`. OpenAPI 3.2 adds `deviceAuthorization`.
- A scheme is applied by an operation through its `security`, or through the root `security` when the operation has none (`security: []` applies nothing). Callbacks follow the path of their operation and webhooks have no path. In OpenAPI 3.2 a requirement can also reference a scheme by URI.
- With `/exclude` a scheme is skipped when every operation that applies it is under a listed path, and schemes applied by no operation are still checked. With `/include` only the schemes applied by operations under the listed paths are checked.
- Schemes reached through `$ref` are reported once, on the referenced definition. Other scheme types and extension keys inside `flows` are ignored.

**Configurable parameters:**

- `allowed-flows` — allowed flows, as an array or a comma-separated list (default: `authorizationCode,clientCredentials`). A blank value falls back to the default.
- `paths` — path patterns to include/exclude, as an array or a comma-separated list; `*` matches one segment and `**` zero or more (default: `/me,/health,/ping,/status`).
- `pathValidationStrategy` — `/include` or `/exclude` (default: `/exclude`).


Noncompliant Code Example (OpenAPI 2)
-------------------------------------

swagger: "2.0"
info:
  version: 1.0.0
  title: Pet Clinic API
paths:
  /owners:
    get:
      security:
        - OwnerPassword: []
      responses:
        200:
          description: Ok
securityDefinitions:
  OwnerPassword:
    type: oauth2
    flow: password \# Noncompliant {{OAR118: Flow 'password' of security scheme 'OwnerPassword' is not allowed. Allowed flows: authorizationCode, clientCredentials.}}
    tokenUrl: https://auth.example.com/token
    scopes: {}

Compliant Solution (OpenAPI 2)
------------------------------

swagger: "2.0"
info:
  version: 1.0.0
  title: Pet Clinic API
paths:
  /owners:
    get:
      security:
        - ClinicApp: []
      responses:
        200:
          description: Ok
securityDefinitions:
  ClinicApp:
    type: oauth2
    flow: application
    tokenUrl: https://auth.example.com/token
    scopes: {}

Noncompliant Code Example (OpenAPI 3)
-------------------------------------

openapi: 3.0.3
info:
  version: 1.0.0
  title: Retail Banking API
security:
  - CustomerOAuth: []
paths:
  /accounts:
    get:
      responses:
        200:
          description: Ok
components:
  securitySchemes:
    CustomerOAuth:
      type: oauth2
      flows:
        authorizationCode:
          authorizationUrl: https://login.example.com/authorize
          tokenUrl: https://login.example.com/token
          scopes: {}
        implicit: \# Noncompliant {{OAR118: Flow 'implicit' of security scheme 'CustomerOAuth' is not allowed. Allowed flows: authorizationCode, clientCredentials.}}
          authorizationUrl: https://login.example.com/authorize
          scopes: {}

Compliant Solution (OpenAPI 3)
------------------------------

openapi: 3.0.3
info:

  title: Retail Banking API
security:

paths:

          description: Ok
components:

      type: oauth2
      flows:
        authorizationCode:
          authorizationUrl: https://login.example.com/authorize
