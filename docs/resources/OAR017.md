It is validated that each route alternates its parts between static and variable parts, starting with the static parts.

**Configurable parameter:** `except` (default: `get,me,search`) — path segments treated as pseudo-parameters that do not break the alternation rule. Both tools implement identical logic.

Examples:

*   `/{id}` → Error (starts with parameter)
*   `/facturas/{id}/{lineId}` → Error (two consecutive parameters)
*   `/facturas/get` → Ok
*   `/facturas/{id}/lineas/get` → Ok
*   `/facturas/{id}` → Ok
*   `/facturas/{id}/lineas/{lineId}` → Ok
*   `/me/items/{id}` → Ok
*   `/users/{id}/me/orders` → Ok

Noncompliant Code Example (OpenAPI 2)
-------------------------------------

```yaml
swagger: "2.0"
info:
  title: Swagger Petstore
  version: 1.0.0
paths:
  /customers/{customerId}/{invoiceId}:
    get:
      parameters:
        - in: path
          name: customerId
          type: integer
          required: true
        - in: path
          name: invoiceId
          type: integer
          required: true
      responses:
        200:
          description: Ok

```
