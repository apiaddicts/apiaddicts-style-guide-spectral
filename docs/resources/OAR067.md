RequestBody and Responses schema property names must be compliant with the camelCase naming convention

The rule checks the property names of every schema of a request body or a response:

- OpenAPI 2: the schema of `in: body` parameters (path item and operation level) and the `schema` of every response.
- OpenAPI 3.x: the media type `schema` of every request body and response (and `itemSchema` in OpenAPI 3.2), in every operation (all HTTP methods, OpenAPI 3.2 `query` and `additionalOperations`), callback and webhook (OpenAPI 3.1+).

Noncompliant Code Example (OpenAPI 2)
-------------------------------------

```yaml
swagger: "2.0"
info:
  version: 1.0.0
  title: Swagger Petstore
paths:
  /user:
    post:
      parameters:
        - in: body
          name: body
          required: true
          schema:
            type: object
            properties:
              first_name: # Noncompliant {{OAR067: RequestBody and Responses schema property names must be compliant with the camelCase naming convention.}}
                type: string
      responses:
        '200':
          description: Success
          schema:
            $ref: '#/definitions/User'
definitions:
  User:
    type: object
    properties:
      user_id: # Noncompliant {{OAR067: RequestBody and Responses schema property names must be compliant with the camelCase naming convention.}}
        type: integer
```

Compliant Solution (OpenAPI 2)
------------------------------

```yaml
swagger: "2.0"
info:
  version: 1.0.0
  title: Swagger Petstore
paths:
  /user:
    post:
      parameters:
        - in: body
          name: body
          required: true
          schema:
            type: object
            properties:
              firstName:
                type: string
      responses:
        '200':
          description: Success
          schema:
            $ref: '#/definitions/User'
definitions:
  User:
    type: object
    properties:
      userId:
        type: integer
```

Noncompliant Code Example (OpenAPI 3)
-------------------------------------

```yaml
openapi: 3.0.3
info:
  version: 1.0.0
  title: Network Assessments
paths:
  /assessments/{assessmentId}/cheapest-solutions:
    get:
      responses:
        '200':
          description: OK
          content:
            application/json:
              schema:
                $ref: '#/components/schemas/cheapestSolution'
components:
  schemas:
    coberturaOrlaEnum: # Compliant: the name of a schema is not a property name
      type: integer
      enum: [219010001, 219010002]
    cheapestSolution:
      type: object
      properties:
        zonaORLA: # Noncompliant {{OAR067: RequestBody and Responses schema property names must be compliant with the camelCase naming convention.}}
          type: integer
        coberturaORLA: # Noncompliant {{OAR067: RequestBody and Responses schema property names must be compliant with the camelCase naming convention.}}
          $ref: '#/components/schemas/coberturaOrlaEnum'
        gvalAQS: # Noncompliant {{OAR067: RequestBody and Responses schema property names must be compliant with the camelCase naming convention.}}
          type: integer
```

Compliant Solution (OpenAPI 3)
------------------------------

```yaml
openapi: 3.0.3
info:
  version: 1.0.0
  title: Network Assessments
paths:
  /assessments/{assessmentId}/cheapest-solutions:
    get:
      responses:
        '200':
          description: OK
          content:
            application/json:
              schema:
                $ref: '#/components/schemas/cheapestSolution'
components:
  schemas:
    coberturaOrlaEnum:
      type: integer
      enum: [219010001, 219010002]
    cheapestSolution:
      type: object
      properties:
        zonaOrla:
          type: integer
        coberturaOrla:
          $ref: '#/components/schemas/coberturaOrlaEnum'
        gvalAqs:
          type: integer
```
