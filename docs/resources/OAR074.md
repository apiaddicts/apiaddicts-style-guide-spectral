Numeric parameters should define minimum and maximum, or a format restriction.

A numeric parameter (`integer` or `number`) is compliant when it defines **both** `minimum` and
`maximum` together, **or** a `format` on its own. Declaring only `minimum` (or only `maximum`) is not
enough — a bound must always be paired with the opposite bound.

Noncompliant Code Example (OpenAPI 2)
-------------------------------------

``` yaml
swagger: '2.0'
info:
  version: 1.0.0
  title: My API
paths:
  /items:
    get:
      summary: Get a list of items
      parameters:
        - name: param1
          in: query
          type: integer # Noncompliant {{OAR074: Numeric parameter should define both 'minimum' and 'maximum', or a 'format' restriction}}
        - name: param2
          in: query
          type: number  # Noncompliant {{OAR074: Numeric parameter should define both 'minimum' and 'maximum', or a 'format' restriction}}
          minimum: 12
      responses:
        200:
          description: A list of items
```

Compliant Solution (OpenAPI 2)
------------------------------

``` yaml
swagger: '2.0'
info:
  version: 1.0.0
  title: My API
paths:
  /items:
    get:
      summary: Get a list of items
      parameters:
        - name: param1
          in: query
          type: integer
          minimum: 0
          maximum: 100
        - name: param2
          in: query
          type: integer
          format: int32
      responses:
        200:
          description: A list of items
```
