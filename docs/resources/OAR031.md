Examples help developers understand the request/response data structure and representation. This rule checks that examples are defined, validating four **independent** levels.

| Level | Where the example must be declared | Message |
| --- | --- | --- |
| Response | A media-type `example`/`examples`, or the root `schema.example` (OpenAPI 2: the response `examples` map or root `schema.example`) | `OAR031: Response must have an example defined` |
| Request body | A media-type `example`/`examples`, or the root `schema.example` | `OAR031: Request body must have an example defined` |
| Parameter | The parameter `example`/`examples`, its `schema.example`, or a media-type example under `content` | `OAR031: Parameter '<name>' must have an example defined` |
| Property | `example`/`examples` on each leaf property of the schema | `OAR031: Property '<name>' is missing an example.` |

The levels are checked **independently**: a whole-body example does not exempt individual properties from having their own example, and per-property examples do not satisfy the response/request-body level. `204` responses are excluded.

Configuration
-------------

All levels are enabled by default. Disable any level by setting its flag to `false` in `functionOptions`:

```yaml
rules:
  apiq:OAR031:
    then:
      function: apq-check-examples-coverage
      functionOptions:
        validateResponse: true     # body example at response level
        validateRequestBody: true  # body example at request-body level
        validateParameter: true    # example at parameter level
        validateProperty: true     # example on each property
```

For example, `validateProperty: false` keeps the response, request-body and parameter checks but stops flagging individual properties.

Noncompliant Code Example (OpenAPI 2)
-------------------------------------

```yaml
swagger: "2.0"
info:
  version: 1.0.0
  title: Swagger Petstore
paths:
  /pets:
    get:
      responses:
        206: # Noncompliant {{OAR031: Response must have an example defined}}
          description: Pet list
          schema:
            $ref: '#/definitions/pets'
definitions:
  pet:
    type: object
    properties:
      name: # Noncompliant {{OAR031: Property 'name' is missing an example.}}
        type: string
      type: # Noncompliant {{OAR031: Property 'type' is missing an example.}}
        type: string
  pets:
    type: object
    properties:
      size: # Noncompliant {{OAR031: Property 'size' is missing an example.}}
        type: integer
      pets:
        type: array
        items:
          $ref: '#/definitions/pet'
```

Compliant Solution (OpenAPI 2)
------------------------------

```yaml
swagger: "2.0"
info:
  version: 1.0.0
  title: Swagger Petstore
paths:
  /pets:
    get:
      responses:
        206:
          description: Pet list
          schema:
            $ref: '#/definitions/pets'
          examples:
            application/json:
              size: 2
              pets:
                - name: Fluffy
                  type: cat
                - name: Sparky
                  type: dog
definitions:
  pet:
    type: object
    properties:
      name:
        type: string
        example: "Snow"
      type:
        type: string
        example: "dog"
  pets:
    type: object
    properties:
      size:
        type: integer
        example: 1
      pets:
        type: array
        items:
          $ref: '#/definitions/pet'
```
