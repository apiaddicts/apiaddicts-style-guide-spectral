A string schema without a format, or with an unrecognized format, may cause developers to use the wrong variable types in the API implementation.

**Note:** Fires when the `format` field is **absent** OR **present but not recognized**. Every string schema must declare one of the valid formats.

**Valid formats:** `date`, `date-time`, `password`, `byte`, `binary`, `email`, `uuid`, `uri`, `hostname`, `ipv4`, `ipv6`, `HEX`, `HEX(16)`, `json`, `xml`, `base64`.

Noncompliant Code Example (OpenAPI 2)
-------------------------------------

swagger: "2.0"
info:
  version: 1.0.0
  title: Swagger Petstore
paths:
  /invoices:
    get:
      responses:
        200:
          description: Invoices.
          schema:
            type: array
            items:
              type: object
              properties:
                name:
                  type: string \# Noncompliant {{OAR037: String schemas must specify a valid format}} — no format
                date:
                  type: string \# Noncompliant {{OAR037: String schemas must specify a valid format}} — invalid format
                  format: 'dd/mm/yyyy'

Compliant Solution (OpenAPI 2)
------------------------------

swagger: "2.0"
info:
  version: 1.0.0
  title: Swagger Petstore
paths:
  /invoices:
    get:
      responses:
        200:
          description: Invoices.
          schema:
            type: array
            items:
              type: object
              properties:
                date:
                  type: string
                  format: date
                id:
                  type: string
                  format: uuid
