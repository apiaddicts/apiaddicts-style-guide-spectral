A string schema without a recognized `format`, and without a valid `pattern` as a fallback, may allow arbitrary, unvalidated input and lead developers to use the wrong variable types in the API implementation.

**Note:** every string schema must be constrained in one of two ways:
- declare a `format` field with a recognized value, or
- if no `format` is declared, declare a `pattern` field that is a non-empty, syntactically valid regular expression.

When no `format` is declared, a non-empty `enum` also satisfies the rule: the `enum` already constrains the allowed values, so a `pattern` is not required. A `format` that is present but not recognized still fires even when an `enum` is declared.

The rule fires when `format` is present but not recognized, or when `format` is absent and there is no valid `pattern` and no non-empty `enum`.

**Valid formats:** `date`, `date-time`, `password`, `byte`, `binary`, `email`, `uuid`, `uri`, `hostname`, `ipv4`, `ipv6`, `HEX`, `HEX(16)`, `json`, `xml`, `base64`.

Noncompliant Code Example (OpenAPI 2)
-------------------------------------

swagger: "2.0"
info:
  version: 1.0.0
  title: Swagger Petstore
paths:
  /invoices:
    get:
      responses:
        200:
          description: Invoices.
          schema:
            type: array
            items:
              type: object
              properties:
                id:
                  type: string \# Noncompliant {{OAR037: String schemas must specify a valid format, or a valid pattern when no format is defined}} — no format, no pattern
                date:
                  type: string \# Noncompliant {{OAR037: String schemas must specify a valid format, or a valid pattern when no format is defined}} — invalid format
                  format: 'dd/mm/yyyy'

Compliant Solution (OpenAPI 2)
------------------------------

swagger: "2.0"
info:
  version: 1.0.0
  title: Swagger Petstore
paths:
  /invoices:
    get:
      responses:
        200:
          description: Invoices.
          schema:
            type: array
            items:
              type: object
              properties:
                id:
                  type: string
                  pattern: '^[A-Z]{3}-[0-9]+$'
                date:
                  type: string
                  format: date

Compliant Solution (OpenAPI 3)
------------------------------

openapi: 3.0.1
info:
  title: Swagger Petstore
  version: 1.0.0
paths:
  /invoices:
    get:
      responses:
        200:
          description: Invoices.
          content:
            application/json:
              schema:
                type: array
                items:
                  type: object
                  properties:
                    id:
                      type: string
                      pattern: '^[A-Z]{3}-[0-9]+$'
                    date:
                      type: string
                      format: date
                    email:
                      type: string
                      format: email
                    channelType:
                      type: string
                      enum:

                        - sms
