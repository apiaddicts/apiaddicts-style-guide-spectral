A paged response not compliant with the standard may cause application issues.

Collections are detected by path. A GET response is evaluated when its status code is 2xx (including 2XX, except 204), the last path segment does not start with a path parameter and the path is not excluded by the `paths` option. Detail paths such as `/users/{id}`, `/files/{name}.json` or `/users/{id}:activate` are never evaluated, while `/users/{id}/orders.{format}` is a collection. Only JSON media types are evaluated: `application/json`, any `+json` suffix, `*/*` and `application/*`, ignoring parameters and case. In Swagger 2.0 they come from the operation `produces`, then from the root one, and a response without `produces` is treated as JSON.

An evaluated response must define a schema, the schema must not be a top-level array, and it must be an object with the paging property, whose name comes from `pagingPropertyName` in paging-schema (`paging` by default). The paging property must comply with paging-schema. Nested paging such as `result.pagination` is checked by setting `pagingPropertyName` to `result` and nesting the paging structure in paging-schema.

The `paths` option is a comma-separated list of patterns matched against the whole path, segment by segment: a pattern without wildcards is an exact match, `*` matches one segment and `**` matches zero or more (`/status,/health,/ping,**/me` by default). With `pathValidationStrategy` set to `/exclude` (default) the matching paths are skipped, and with `/include` only the matching paths are evaluated. A configured value replaces the default list, and an empty value excludes nothing.

Noncompliant Code Example (OpenAPI 2)
-------------------------------------

swagger: "2.0"
info:
  version: 1.0.0
  title: Swagger Petstore
paths:
  /endpoint:
    get:
      responses:
        206:
          description: Ok
          schema:
            type: object
            properties:
              items:
                type: array
                items:
                  type: string
        204:
          description: No content
        400:
          description: Error
        default:
          description: Unknown

Compliant Solution (OpenAPI 2)
------------------------------

swagger: "2.0"
info:
  version: 1.0.0
  title: Swagger Petstore
paths:
  /endpoint:
    get:
      responses:
        206:
          description: Ok
          schema:
            $ref: '#/definitions/response'
        204:
          description: No content
        400:
          description: Error
          schema:
            $ref: '#/definitions/response'
        default:
          description: Unknown

definitions:
  response:
    type: object
    allOf:
      - $ref: '#/definitions/paged\_response'
    properties:
      payload:
        type: object
        properties:
          values:
            type: array
            items:
              type: string
  paged\_response:
    type: object
    properties:
      paging:
        type: object
        properties:
          start:
            type: integer
          limit:
            type: integer
          total:
            type: integer
          numPages:
            type: integer
          links:
            type: object
            properties:
              self:
                $ref: '#/definitions/link'
              first:
                $ref: '#/definitions/link'
              previous:
                $ref: '#/definitions/link'
              next:
                $ref: '#/definitions/link'
              last:
                $ref: '#/definitions/link'
            required:
              - self
              - previous
              - next
        required:
          - start
          - limit
          - links
  link:
    type: object
    properties:
      href:
        type: string
