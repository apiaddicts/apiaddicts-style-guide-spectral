A wrong scope definition may cause problems to import the API definition into WSO2.

Every scope under `x-wso2-security.apim.x-wso2-scopes` must define a non-empty `name`, `key` and
`roles`, and the scopes container itself must not be `null` or empty.

Noncompliant Code Example (OpenAPI 2)
---------------------------------------------------------------------------------------

swagger: "2.0"
x-wso2-security:
  apim:
    x-wso2-scopes:
    - name: read
      roles: READ_ROLE       # missing 'key'
    - name: write
      roles:                 # 'roles' is null
      key: write

Compliant Solution (OpenAPI 2)
--------------------------------------------------------------------------------------

swagger: "2.0"
x-wso2-security:
  apim:
    x-wso2-scopes:
    - name: read
      key: read
      roles: READ_ROLE
    - name: write
      key: write
      roles: WRITE_ROLE

Noncompliant Code Example (OpenAPI 3)
--------------------------------------------------------------------------------------

openapi: "3.0.0"
x-wso2-security:
  apim:
    x-wso2-scopes: []        # empty (or null) container

Compliant Solution (OpenAPI 3)
--------------------------------------------------------------------------------------

openapi: "3.0.0"
x-wso2-security:
  apim:
    x-wso2-scopes:
    - name: read
      key: read
      roles: READ_ROLE
    - name: write
      key: write
      roles: WRITE_ROLE
