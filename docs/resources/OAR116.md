Every API path must match the configured regular expression.

By default the pattern only requires each path to start with `/` (`^/`), which every well-formed OpenAPI path already satisfies. Clients can override it with a stricter expression to enforce their own path convention.

Parameters
----------

- `pattern` (default `^/`): regular expression every API path must match. Matching is unanchored (`RegExp.test`), so `^/` behaves as "must start with /". Provide your own anchors (e.g. `^/v[0-9]+/`) to enforce a stricter convention.

Noncompliant Code Example (default pattern `^/`)
-----------------------------------------------

openapi: 3.0.1
info:
  title: Swagger Petstore
  version: 1.0.0
paths:
  pets: \# Noncompliant {{OAR116: Path does not match the required pattern: ^/}}
    get:
      responses:
        200:
          description: Ok

Compliant Solution (default pattern `^/`)
-----------------------------------------

openapi: 3.0.1
info:
  title: Swagger Petstore
  version: 1.0.0
paths:
  /pets:
    get:
      responses:
        200:
          description: Ok

Noncompliant Code Example (custom pattern `^/v[0-9]+`)
------------------------------------------------------

openapi: 3.0.1
info:
  title: Swagger Petstore
  version: 1.0.0
paths:
  /pets: \# Noncompliant {{OAR116: Path does not match the required pattern: ^/v[0-9]+}}
    get:
      responses:
        200:
          description: Ok

Compliant Solution (custom pattern `^/v[0-9]+`)
-----------------------------------------------

openapi: 3.0.1
info:
  title: Swagger Petstore
  version: 1.0.0
paths:
  /v1/pets:
    get:
      responses:
        200:
          description: Ok
