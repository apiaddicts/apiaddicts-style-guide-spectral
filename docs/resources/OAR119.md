The authorizationUrl of every OAuth2 flow must match the pattern allowed by the organization.

**Rules:**
- Applies to the `authorizationUrl` of the `oauth2` security schemes: on the scheme itself in OpenAPI 2, and on every flow that declares it in OpenAPI 3. The issue is reported on the URL.
- The URL must match `pattern`. By default it must be an HTTPS URL on a domain whose path ends in `/authorize`, without query string or fragment.
- `tokenUrl`, `refreshUrl`, `deviceAuthorizationUrl` and `oauth2MetadataUrl` are not checked.
- A scheme is applied by an operation through its `security`, or through the root `security` when the operation has none (`security: []` applies nothing). Callbacks follow the path of their operation and webhooks have no path. In OpenAPI 3.2 a requirement can also reference a scheme by URI.
- With `/exclude` a scheme is skipped when every operation that applies it is under a listed path, and schemes applied by no operation are still checked. With `/include` only the schemes applied by operations under the listed paths are checked.
- Schemes reached through `$ref` are reported once, on the referenced definition. Other scheme types and extension keys inside `flows` are ignored.

**Configurable parameters:**

- `pattern` — regular expression the URL must match, without anchors (write `^...$` to match the whole URL); a leading `(?i)` ignores case (default: `^https://[A-Za-z0-9-]+(\.[A-Za-z0-9-]+)+(:[0-9]+)?(/[^/?#]+)*/authorize$`). A blank or invalid value falls back to the default.
- `paths` — path patterns to include/exclude, as an array or a comma-separated list; `*` matches one segment and `**` zero or more (default: `/me,/health,/ping,/status`).
- `pathValidationStrategy` — `/include` or `/exclude` (default: `/exclude`).


Noncompliant Code Example (OpenAPI 2)
-------------------------------------

swagger: "2.0"
info:
  version: 1.0.0
  title: Pet Clinic API
paths:
  /owners:
    get:
      security:
        - OwnerOAuth: []
      responses:
        200:
          description: Ok
securityDefinitions:
  OwnerOAuth:
    type: oauth2
    flow: accessCode
    authorizationUrl: http://login.example.com/oauth/authorize \# Noncompliant {{OAR119: authorizationUrl 'http://login.example.com/oauth/authorize' of flow 'accessCode' in security scheme 'OwnerOAuth' does not match the allowed pattern: ^https://[A-Za-z0-9-]+(\.[A-Za-z0-9-]+)+(:[0-9]+)?(/[^/?#]+)*/authorize$}}
    tokenUrl: https://login.example.com/oauth/token
    scopes: {}

Compliant Solution (OpenAPI 2)
------------------------------

swagger: "2.0"
info:
  version: 1.0.0
  title: Pet Clinic API
paths:
  /owners:
    get:
      security:
        - OwnerOAuth: []
      responses:
        200:
          description: Ok
securityDefinitions:
  OwnerOAuth:
    type: oauth2
    flow: accessCode
    authorizationUrl: https://login.example.com/oauth/authorize
    tokenUrl: https://login.example.com/oauth/token
    scopes: {}
