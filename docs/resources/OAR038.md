The 201 response schema of a POST operation may only use the allowed top-level properties (by default `data` or `error`), each with at least one sub-property, and must declare every required one.

**Rules:**
- Only applies to `201` responses of `POST` operations under `paths`, on paths selected by `paths`/`pathValidationStrategy`.
- Top-level property names must be one of the allowed names (case-sensitive). A missing allowed name is not an issue.
- Every allowed property that appears must contain at least one sub-property.
- Every required property must appear at the top level.
- Properties are merged from `allOf` (not from `oneOf`/`anyOf`), and each media type is checked separately.

**Configurable parameters:**

- `data-property` — name accepted next to `error` when `allowed-properties` is not set (default: `data`).
- `allowed-properties` — top-level property names accepted, as an array or a comma-separated list (default: empty, which means `[data-property, error]`).
- `required-properties` — top-level property names that must appear, as an array or a comma-separated list (default: empty). Each one should also be listed in `allowed-properties`.
- `paths` — paths to include/exclude, exact match, as an array or a comma-separated list (default: `/me,/health,/ping,/status`).
- `pathValidationStrategy` — `/include` or `/exclude` (default: `/exclude`).


Noncompliant Code Example (OpenAPI 2)
-------------------------------------

swagger: "2.0"
info:
  version: 1.0.0
  title: Swagger Petstore
paths:
  /endpoint:
    post:
      responses:
        201:
          description: Ok
          schema:
            $ref: '#/definitions/response'
        204:
          description: No content

definitions:
  response:
    type: object
    properties:
      result: \# Noncompliant {{OAR038: Response property must be named 'data' or 'error'}}
        type: object
        properties:
          id:
            type: string
