Path parameter names, query parameter names, object names, and property names with more than two words must follow the configured naming convention.

**Configurable parameters:**

- `naming-convention` — `snake_case` (default), `kebab-case`, `camelCase` or `UpperCamelCase`, trimmed and case-insensitive. Any other value falls back to `snake_case`. The former option name `namingConvention` is still read when `naming-convention` is not set.

| Convention | Compliant names | Noncompliant names |
|---|---|---|
| `snake_case` | `pet_id`, `address_line2`, `_links`, `id` | `petId`, `pet-id`, `PetId` |
| `kebab-case` | `pet-id`, `address-line2`, `id` | `petId`, `pet_id`, `PetId` |
| `camelCase` | `petId`, `addressLine2`, `oauth2Token`, `id` | `PetId`, `pet_id`, `pet-id`, `customerID` |
| `UpperCamelCase` | `PetId`, `AddressLine2`, `Id` | `petId`, `pet_id`, `id`, `CustomerID` |

The query names `$init`, `$start`, `$limit`, `$total`, `$expand`, `$orderby`, `$select`, `$exclude` and `$filter` are accepted in every convention. An empty name, or a name with spaces, dots, slashes or braces, follows none.

Configuration Example:
---------------------------------

```yaml
rules:
  apiq:OAR012:
    resolved: false
    given: "$"
    then:
      function: apq-parameter-naming-convention
      functionOptions:
        naming-convention: "snake_case" # Default naming convention.
```

Noncompliant Example (OpenAPI 2 - camelCase convention):
---------------------------------

```yaml
swagger: "2.0"
info:
  title: Swagger Petstore
  version: "1.0"
paths:
  /pets/{pet-id}:
    get:
      parameters:
        - in: path
          name: pet-id
          type: integer
          required: true
        - in: query
          name: PET_TYPE
          type: string
      responses:
        200:
          description: Ok
          schema:
            type: object
            properties:
              pet_name:
                type: string
```

Compliant Example (OpenAPI 2 - camelCase convention):
-------------------------------

```yaml
swagger: "2.0"
info:
  title: Swagger Petstore
  version: "1.0"

                type: string
```

Noncompliant Example (OpenAPI 3 - snake_case convention):
---------------------------------

```yaml
openapi: "3.0.0"
info:
  title: Swagger Petstore
  version: "1.0"
paths:
  /pets/{petId}:
    get:
      parameters:
        - in: path
          name: petId
          schema:
            type: integer
          required: true
        - in: query
          name: pet-Type
          schema:
            type: string
      responses:
        200:
          $ref: '#/components/responses/pet_response'
components:
  responses:
    pet_response:
      description: Ok
      content:
        application/json:
          schema:
            allOf:
              - $ref: '#/components/schemas/standard_response'
              - type: object
                properties:
                  petName:
                    type: string
  schemas:
    standard_response:
      type: object
      properties:
        result:
          type: object
          properties:
            httpCode:
              type: integer
```
