The defined media types must conform to the [RFC6838](https://tools.ietf.org/html/rfc6838) and [RFC7231](https://tools.ietf.org/html/rfc7231). This ensures that a tool can rely on the declared media type to generate appropriate code to handle the parsing of output.

Valid media types include standard types (`application/json`, `text/plain`), vendor-specific types (`application/vnd.ms-excel`, `application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`), structured suffixes (`application/ld+json`), parameterized types (`text/plain; charset=utf-8`), and media ranges with wildcards (`image/*`, `*/*`).

Noncompliant Code Example (OpenAPI 2)
-------------------------------------

```yaml
swagger: "2.0"
info:
    version: 1.0.0
    title: Swagger Petstore
produces:
    - application/json
    - text/*             # Noncompliant {{OAR044: Declared mime type should conform to RFC6838}}
consumes:
    - application/json
    - text/*             # Noncompliant {{OAR044: Declared mime type should conform to RFC6838}}
paths:
    /pets:
    get:
        produces:
        - application    # Noncompliant {{OAR044: Declared mime type should conform to RFC6838}}
        - text/plain
        consumes:
        - application    # Noncompliant {{OAR044: Declared mime type should conform to RFC6838}}
        - text/plain
        responses:
        '200':
            description: some operation
```

Compliant Solution (OpenAPI 2)
------------------------------

```yaml
swagger: "2.0"
info:
    version: 1.0.0
    title: Swagger Petstore
produces:
    - application/json
    - text/plain
    - application/vnd.ms-excel
    - application/vnd.openxmlformats-officedocument.spreadsheetml.sheet
    - application/ld+json
consumes:
    - application/json
    - text/plain
    - application/vnd.ms-excel
paths:
    /pets:
    get:
        produces:
        - application/json
        - text/plain
        consumes:
        - application/json
        - text/plain
        responses:
        '200':
            description: some operation
```
